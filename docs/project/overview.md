# 專題概述：換你教－校園技能交換 App

**英文名稱：** SwapTeach: A Campus Skill-Exchange App

這是**最新版**的專題概述，以已提交的「教育AI組」概述文件為基礎，之後隨專題調整持續更新。已提交的原始版本見 [docs/competition/submissions/](../competition/submissions/)。專有名詞定義見 [CONTEXT.md](../../CONTEXT.md)。

## 要解決的問題

- 大學生想在課業之外學新技能（第二外語、樂器、影片剪輯、程式設計等），但補習班與付費課程很貴。
- 校園裡有很多有專長的同學，但沒有管道知道「誰會什麼、誰想學什麼」。在社群平台發文徵求互教，貼文容易被洗掉，也看不出對方的程度與可配合時間。
- 就算找到人，同儕互教還有三個問題：
  1. 會的人不一定會教，不知道第一次見面從哪裡開始。
  2. 雙方課表不同，約時間要來回很多次。
  3. 教完沒有紀錄，不知道對方學到多少。

## 核心概念：以技能換技能

- 每位使用者有一張**技能卡**，寫著會的技能與想學的技能。
- 參考交友軟體的**滑卡**：右滑表示想跟對方學、左滑略過；雙方都右滑才算**配對**成功。
- 只靠一對一互換常會「我想學你的，但你不想學我的」，所以加入兩個機制：
  - **環狀配對**：系統找第三人甚至更多人，形成 A 教 B、B 教 C、C 教 A 的循環。
  - **時間幣**：教一小時得一枚，可以用來向任何人學一小時；不論技能，每個人的一小時都等值。

## 功能

1. **技能卡**：填寫會的技能、想學的技能、程度與可配合時段。
2. **滑卡配對**：雙方都右滑後才開啟聊天。
3. **聊天與預約**：配對後討論教學內容，預約見面的時間與地點。
4. **共同空堂自動排程**：匯入課表後，自動找出雙方的共同空堂。
5. **AI 學習計畫**：依學習目標與預計見面次數，產生每次見面的教學大綱，供教學者參考與修改。
6. **AI 課後回顧**：依雙方的課後紀錄，產生重點整理與練習題。
7. **時間幣與環狀配對**：記錄每位使用者的教學與學習時數，支援多人循環交換。
8. **互評與技能徽章**：見面後互相評分；累積教學時數可得徽章；紀錄可匯出為學習歷程。
9. **校內地點推薦與收藏清單**：建議圖書館討論室等公開場地；有興趣但未決定的技能卡可先收藏。

## AI 的角色

AI 是**輔助同儕教學**，不是取代教學。實際教學仍然是人對人。

| 用途 | 輸入 | 輸出 |
|---|---|---|
| 配對推薦 | 技能相符程度、程度差距、共同空堂 | 推薦對象、環狀配對組合 |
| AI 學習計畫 | 技能名稱、學習者自評程度、學習目標、見面次數 | 每次見面的主題與練習建議（草稿，教學者確認後才給學習者） |
| AI 課後回顧 | 雙方的課後紀錄 | 重點整理與練習題 |

送給語言模型的內容不包含姓名、學號等個人資料。

## 特色

1. AI 幫教的人備課，降低「不知道怎麼教」的門檻。
2. AI 是輔助：學習計畫與練習題都是草稿，教學者可以修改，確認後才提供。
3. 環狀配對與時間幣讓技能不必剛好兩兩對上也能交換。
4. 不需要花錢。
5. 從教中學；教學時數、徽章與評價可以匯出成學習歷程。
6. 限定校內：以學校信箱驗證身分；課表只用來計算共同空堂。

## 技術規劃（尚未定案）

| 層 | 技術 |
|---|---|
| 前端 | Flutter（同時支援 Android 與 iOS） |
| 後端 | Python FastAPI |
| 資料庫 | PostgreSQL（技能卡、配對紀錄、評價、時間幣帳本） |
| 配對演算法 | 使用者為節點，「甲會的技能是乙想學的」為有向邊，在圖上找短的環作為環狀配對候選；一般推薦依技能相符程度、共同空堂多寡與過去評價排序 |
| 語言模型 | 大型語言模型 API |
| 推播 | Firebase Cloud Messaging（配對成功、預約提醒） |
| 部署 | 雲端主機（或向系上申請的 VM） |

## 使用對象與環境

- **對象：** 大學生、研究生（語言交換、研究工具）、社團與系學會（找美編、剪輯、主持等專長）。
- **硬體：** Android 或 iOS 手機。
- **網路：** 配對、聊天與推播都需要連網。
- **帳號：** 以學校信箱註冊並驗證。

## 待解決問題

1. **⚠️ 20 萬筆公開資料。** 課程要求使用 Public Data、Open Data 或自行爬取 20 萬筆以上資料。目前規劃的資料來源是使用者自填的技能卡、評價、課後紀錄、使用者匯入的課表，以及學校公開的場地資訊，**都不是 20 萬筆的公開資料**。需要找到與專題相關的大型公開資料來源（例如課程資料、技能分類、教學資源等）並說明它在系統中的用途。
2. **⚠️ 程式語言。** 課綱寫要用 Java 寫 Android 程式；我們規劃用 Flutter 與 Python。需要向老師確認。
3. **名詞待釐清。** 見 [CONTEXT.md](../../CONTEXT.md) 最後的「待釐清」段落。
