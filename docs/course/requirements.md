## 專題要求（務必具備）

期末專題主題是「創意 APP 專題設計」：設計一套平板或手機 APP，結合資料庫與公開資料（Public/Open Data）。

| # | 要求 | 我們的狀況 |
|---|---|---|
| 1 | 4–5 人一組，第一次上課當天（9/16）自行分組 | ✅ 已分組 |
| 2 | 使用資料庫（DBMS 不限） | ✅ 規劃使用 PostgreSQL |
| 3 | **網路連線版**，不能是單機版（系上 VM 或免費雲端服務都可以） | ✅ 規劃為 App + 雲端後端 |
| 4 | **結合 AI 功能**（自行發揮創意；可以使用別人的 AI API） | ✅ AI 配對推薦、AI 學習計畫、AI 課後回顧 |
| 5 | Public Data、Open Data 或自行爬取 **20 萬筆以上**資料，必須合法取得（⚠️ 第一堂課口頭說「220 萬個欄位」，見 [first-lecture.md](first-lecture.md#專題要求)） | ⚠️ **尚未解決**，見 [專題概述](../project/overview.md#待解決問題) |
| 6 | 使用 GitHub | ✅ 本 repo（未使用 GitHub 扣 5 分） |
| 7 | 可借系上平板（每組 1 部）+ 1 部 VM，向力文助教申請 | ⚠️ 待決定是否申請 |

## 第一堂課的口頭補充

以下來自第一堂課逐字稿（非官方），詳見 [first-lecture.md](first-lecture.md)。

- **最好做 APP。** 不做 APP（例如做網頁）必須說明為什麼比 APP 更有創意；沒有理由的「我想做網頁」不接受。
- **先查有沒有人做過。** 決定題目前先調查既有的類似產品與它們做到什麼程度。
- **要看得到資料庫設計的過程**（例如在 GitHub 上），否則同學可以用這個理由打 X。

## 課程大綱中的其他規定

- **⚠️ 待確認：** 課綱寫「本課程需要在 Android 平台上撰寫 JAVA 程式」。我們規劃用 Flutter（Dart）與 Python，需要確認老師是否接受。投影片中的專題要求沒有限制程式語言；老師在第一堂課也說 Android 教科書「只要你可以上手都 OK」，看起來不嚴格，但仍需確認。
- **⚠️ 待確認：** 課綱的評量欄寫「務必參加 2025 第 30 屆大專校院資訊應用服務創新競賽」，年份應為舊資料；投影片寫的是 2026 第 31 屆。
- **學術誠信：** 專題必須是自己完成的。可以和老師、助教討論，也可以和同學討論一般概念，但不可分享設計或實作。違反者可能該作業或整門課不及格。
- 課綱稱期末專題為「微型產學合作」。
