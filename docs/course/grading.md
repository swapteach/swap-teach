## 同學互評（期中提案與期末發表都適用）

**分數 = 100 × (1 − 被打 X 總數 ÷ 總評分人數)**

- 報告順序抽籤決定；由同學推舉一位主持人（主持人學期成績 +1 分）。
- 每個人都要評分，當場分開評分並交評分表。
- 老師在現場只聽，不發言、不給意見。同學可以發問，但不能故意帶風向。
- 所有組別在同一次上課報告完。**一開始報告就不再發評分表**，遲到視同缺席。
- 上廁所必須 2 分鐘內回來；只要有一組沒聽到，就沒收評分表、視同缺席。
- **缺席者不能評分，而且 X 的個數會算到缺席者自己身上。**
- 每個人至少要打 5 個 X（15 組 × 1/3 = 5），組數更多就更多。
- 打 X 一定要寫理由，而且只能針對報告與製作內容（「討厭報告者」「聲音不好聽」不能當理由）。
- 老師在第一堂課補充（非官方逐字稿，見 [first-lecture.md](first-lecture.md#期中與期末發表)）：
  - 評分分三個面向：**完整度、創意、可用性**。
  - 合理的 X 理由例如：介面不夠好看、可用性低、資料庫筆數不對、沒有用 GitHub、**看不到資料庫設計的過程**。
  - 拉票或串通（例如請人不要打自己 X）的話，X 會算到這些人那一組身上。
  - 發表時沒有成品、或 Demo 到一半當掉，算「屍體」，不評分；沒有成品的組別不會及格。

## 組內貢獻比例

整組分數會依組員互評的貢獻比例分給每個人。每位組員填一欄，給每個人（包括自己）一個比例，總和為 1。

- **比例調整：** 組員 i 的 X_i = (所有組員給 i 的比例的平均) − 1/人數
- **個人分數：** 整組分數 × (1 + X_i)
- 投影片另寫「不到 0.01 直接去除評分」。老師在第一堂課說明：有人給 0.001 的話，就當作這個人沒有做，**期末專題 0 分**。

範例（4 人組，整組 70 分）：C 拿到的比例是 0.3、0.25、0.2、0.3，平均 0.2625，X = 0.0125，分數 = 70 × 1.0125 ≈ 71。

投影片中的特殊情況：

| 情況 | 結果 |
|---|---|
| 大家都給 0.25 | 每人都拿整組分數 |
| 每個人都只給自己 1 | 整組 0 分（「亂來」） |
| 全部填 0 | 整組 0 分 |
| 分成兩個小團體互給 | 整組分數打對折（「搞怪」）；老師說是開玩笑的，沒有發生過 |
