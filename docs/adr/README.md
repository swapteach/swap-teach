# 重大決策紀錄（ADR）

ADR（Architecture Decision Record）記錄**重大的決策**以及當時的理由，讓之後的人（包括未來的自己）知道「為什麼當初這樣做」。

## 什麼時候要寫 ADR

三個條件**都**符合才寫：

1. **難以逆轉：** 之後改變主意的代價很大（例如換資料庫、改變時間幣的規則）。
2. **沒有背景會覺得奇怪：** 未來的人看到會問「為什麼要這樣做？」
3. **有真正的取捨：** 當時有其他可行的選項，我們因為特定理由選了這個。

一般的決策記在 [LOG.md](../../LOG.md) 就好。

## 格式

檔名：`NNNN-簡短英文標題.md`，例如 `0001-postgresql-as-database.md`。編號依序遞增。

```markdown
# NNNN. 標題

- **日期：** YYYY-MM-DD
- **狀態：** 提議中 / 已採用 / 已被 NNNN 取代

## 背景

遇到什麼問題、有什麼限制。

## 決策

我們決定怎麼做。

## 考慮過的選項

- 選項 A：優點 / 缺點
- 選項 B：優點 / 缺點

## 影響

這個決策帶來的後果，包括好的與壞的。
```

寫完 ADR 後，在 LOG.md 新增一筆紀錄並連結它。
